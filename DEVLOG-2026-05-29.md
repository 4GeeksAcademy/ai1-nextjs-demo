# Dev Log — May 29, 2026

## Major Features & Refactors

### 1. Genre Domain Modeling

- Added `IGenre` support for hierarchy with `parent_genre_id` and recursive `subgenres`.
- Extended `IBook` with optional `genres` for resolved many-to-many associations.
- Kept type changes backward compatible by using optional fields.

### 2. Database Schema for Genres

- Added `genres` table with self-referencing parent relationship.
- Added `book_genres` join table for many-to-many between books and genres.
- Added supporting indexes for `book_genres` lookup performance.
- Seeded hierarchical sample genres, including:
  - Fiction -> Sci-Fi -> Cyberpunk
- Seeded initial `book_genres` assignments for existing books.

### 3. Library Adapter Enhancements

- Expanded library adapter contract and implementations to support:
  - read genre tree
  - read genres by book
  - assign genres to books
  - create genre
  - update genre
  - delete genre
- Updated both database and in-memory adapters to keep behavior aligned.
- Ensured book reads (`getAll`, `findById`) return assigned genres when available.

### 4. Server Actions and Data Facade

- Added genre-aware server actions for:
  - creating/updating/deleting genres
  - assigning genres to books
  - fetching available genres for forms
- Updated data facade (`src/data/library.ts`) to expose all genre operations in one place.

### 5. UI: Genre Management Interface

- Added dedicated genre routes:
  - `/genres` (hierarchical list)
  - `/genres/new` (create)
  - `/genres/[id]` (edit/delete)
- Added navigation links in the top navbar for genre workflows.
- Added delete confirmation prompt before destructive genre removal.

### 6. UI: Book Genre Assignment

- Added multi-select genre assignment panel to `/catalog/[id]`.
- Added multi-select genre selection in `/catalog/new` create-book flow.
- Preserved hierarchical readability in selectors with indentation and/or path labeling.
